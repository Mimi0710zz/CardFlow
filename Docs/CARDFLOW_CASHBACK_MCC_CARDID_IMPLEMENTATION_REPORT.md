## Percentage display implementation

`formatCashbackRate()` formats the stored decimal rate as a Vietnamese percentage with exactly one decimal digit. Stored values are not changed. The Cashback Program table now displays `0.05`, `0.068`, `0.168`, and `0.20` as `5,0%`, `6,8%`, `16,8%`, and `20,0%`.

The dashboard currently does not display a cashback rate; its progress percentage continues to use the existing integer progress formatter.

## Bank-code source of truth and Card ID generation

New Card IDs continue to be generated by resolving the selected `bankId` in `state.banks`, reading `bank.code`, normalizing the card name, and building `<BANK_CODE>-<NORMALIZED_CARD_NAME>`.

No Sacombank/SCB hardcoded mapping is used by new-card generation. With master data `Sacombank / SACOM`, a new Cashback card is `SACOM-CASHBACK`; the separate `SCB / SCB` bank continues to generate `SCB-*`.

## Legacy Card ID migration behavior

Legacy Card IDs are deliberately preserved. No automatic `SCB-*` to `SACOM-*` rename is claimed or performed.

The audit found direct Card ID references in cashback programs, transactions, payments, cashback receipts, and card-based calculations/exports. Shared-limit fields can also embed Card IDs in `limitGroup`, `limitGroupId`, and related group values. A collision-free rename cannot be guaranteed for every synced user dataset without inspecting that runtime dataset, so preserving IDs is safer and keeps Google Drive/history references intact.

## Cashback Program ID

The editable `Mã chương trình` field was removed from Add/Edit UI. On Add, the app generates `<CARD_ID>-<NORMALIZED_PROGRAM_NAME>`, validates uniqueness, and rejects an invalid/duplicate ID. On Edit, the existing ID is preserved even if card or program name changes.

## MCC multi-select and “Tất cả”

The manual comma-separated textarea was replaced with the existing compact, collapsed, touch-friendly multi-select pattern. Options are loaded dynamically from `state.mccCategories` and displayed as `<Tên nhóm> (<MCC>)`.

`Tất cả` uses the explicit representation:

```json
{
  "allMcc": true,
  "mccCategoryIds": []
}
```

Specific selection uses stable MCC master IDs. Selecting `Tất cả` clears individual selections; selecting an individual option clears `Tất cả`. The collapsed control provides a compact readable summary.

## Cashback eligibility

MCC qualification now checks `allMcc` first. If true, any transaction MCC passes. Otherwise, the transaction is resolved against MCC master data by stable ID/name/code and must match a selected `mccCategoryIds` entry. Channel checks remain independent and unchanged.

## Legacy MCC migration

Canonicalization converts existing `categories` arrays to stable MCC IDs where a matching MCC ID, name, or code exists. A legacy empty category list retains its former meaning as all MCC via `allMcc: true`. Legacy unmatched names are preserved as a compatibility fallback instead of being silently discarded. The migration is idempotent and does not reset data.

Renaming an MCC keeps program display compatibility through stable IDs. Deleting an MCC is blocked when transactions or cashback programs still reference it.
